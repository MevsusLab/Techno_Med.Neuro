# Техническое руководство и архитектура программного комплекса «TechnoMedNeuro»

## 1. Назначение и концепция системы

Программный комплекс **«TechnoMedNeuro»** представляет собой модульную научно-исследовательскую программную систему, предназначенную для бесконтактного объективного скрининга неврологических дисфункций, количественной биомаркерной квантификации двигательных и вегетативных нарушений, специализированного ассистивного взаимодействия и интеллектуальной поддержки принятия врачебных решений.

Система разработана для применения в исследовательских и образовательных лабораториях (включая Национальный детский технопарк) и обеспечивает работу со стандартными доступными сенсорами: потребительской веб-камерой (RGB, 640x480 @ 30 FPS) и стандартным микрофоном (16–96 кГц).

В состав комплекса входят 6 функционально независимых исследовательских модулей:
1. **Анализ тремора верхних конечностей** (`tremor_engine.py`, `capture_worker.py`): спектральный и кинематический анализ колебаний дистальной фаланги пальца с дифференциацией паркинсонического (4,0–6,5 Гц) и постурально-кинетического (6,5–12,0 Гц) тремора.
2. **Количественная оценка нейромимики и экспрессий** (`facial_engine.py`, `face_capture.py`): трехфазный протокол теста FAST (покой, улыбка, брови), расчет индекса асимметрии лица (ASI) и дифференциация центрального vs периферического пареза лицевого нерва по 468 ориентирам Face Mesh.
3. **Бесконтактная фотоплетизмография (rPPG)** (`rppg_engine.py`, `rppg_capture.py`): детекция пульсовой волны (ЧСС / BPM) на основе вариаций поглощения зеленого спектрального канала в трех анатомических зонах лица (лоб, щеки).
4. **Моторный таппинг-тест UPDRS 3.4** (`motor_engine.py`, `motor_capture.py`, `motor_protocol.py`): объективизация кинематики смыкания пальцев, расчет темпа, коэффициента вариабельности (CV) и линейного декремента амплитуды (брадикинезия/истощаемость).
5. **Айтрекинг и ассистивная коммуникация (AAC)** (`gaze_engine.py`, `gaze_capture.py`, `aac_speech.py`, `phrase_graph.py`): интерфейс управления взглядом по положению радужки с компенсацией наклона головы, байесовской классификацией, автоматом фиксации Dwell Engine, синтезом речи SAPI5 и предиктивным графом фраз.
6. **Акустический анализ голосовых биомаркеров** (`voice_engine.py`, `voice_capture.py`, `voice_dependencies.py`): спектральный и микродевиационный анализ стабильной фонации гласного [а:], расчет F0, Jitter (local, RAP), Shimmer (local, APQ5), гармоничности HNR и 13 коэффициентов MFCC по нормативам MDVP/Praat.

Интеграционный уровень формируют:
- **Мультимодальная система поддержки врачебных решений (CDSS)** (`cdss_dashboard.py`, `session_diagnostics.py`): ориентированный двудольный граф клинической онтологии (9 формализованных биомаркеров $\to$ 6 синдромальных гипотез).
- **Темпоральный граф пациентов** (`patient_graph.py`, `patient_cards_drawer.py`): графовая база истории болезни (`TemporalPatientGraph`) с оценкой динамики («УЛУЧШЕНИЕ», «СТАБИЛЬНО», «УХУДШЕНИЕ»), поиском клинических прецедентов (Clinical Twins) и SHA-256 криптозащитой персональных данных.

> [!IMPORTANT]
> **Клинический статус:** Программный комплекс является научно-исследовательским инженерным прототипом и не является сертифицированным медицинским изделием. Результаты анализа не являются диагнозом и служат исключительно для вспомогательной объективизации биомаркеров в научно-исследовательских целях.

## 2. Архитектура процессов и межпроцессное взаимодействие (IPC)

Главной инженерной задачей при работе с нативными библиотеками компьютерного зрения (OpenCV, MediaPipe) и аудиозахвата (PortAudio) является предотвращение блокировки графического интерфейса пользователя (GUI) и обеспечение отказоустойчивости при сбоях драйверов оборудования.

```text
+-------------------------------------------------------------------+
|               Главный процесс GUI (PyQt6 Event Loop)              |
|  MainWindow / Виджеты страниц / Matplotlib Canvases / Панели      |
+-------------------------------------------------------------------+
                               |
              spawn процесса   |  QThread (ProcessCaptureWorker)
                               v
+-------------------------------------------------------------------+
|           Супервизор сессии (QThread в контексте GUI)             |
|  - Контроль жизненного цикла и сторожевых таймеров (Watchdog)     |
|  - Кооперативная остановка (multiprocessing.Event)                |
|  - Принудительное завершение (terminate / kill) при зависании     |
+-------------------------------------------------------------------+
                               |
        Однонаправленный канал | multiprocessing.Pipe(duplex=False)
        (превью, фаза, метрики)|
                               v
+-------------------------------------------------------------------+
|         Изолированный дочерний процесс видеозахвата/ЦОС           |
|  - Владеет дескриптором камеры (cv2.VideoCapture)                 |
|  - Инференс нейросетевых моделей MediaPipe Tasks API              |
|  - Потоковая фильтрация и формирование измерительных пакетов      |
|  - Гарантированное освобождение нативных ресурсов в cleanup       |
+-------------------------------------------------------------------+
```

### 2.1. Изоляция критических подсистем (Process Isolation)

1. **Контекст создания процессов `spawn`:** На платформе Windows вызов `multiprocessing.get_context("spawn")` гарантирует создание чистого экземпляра интерпретатора Python без разделения незащищенного нативного адресного пространства. Для поддержки скомпилированных бинарных сборок точка входа `app.py` вызывает `multiprocessing.freeze_support()`.
2. **Проблема нативных блокировок:** Драйверы видеокамер и C++ рантайм MediaPipe исполняются на уровне платформенно-зависимых динамических библиотек. При аппаратном сбое веб-камеры или задержке шины USB стандартный поток `threading.Thread` не может быть безопасно прерван (метод `QThread.terminate()` признан нестабильным и ведет к утечкам дескрипторов и deadlock в Qt). Изоляция в отдельном процессе ОС позволяет принудительно терминировать дочерний процесс (`child_process.terminate()` / `kill()`) и освободить видеоустройство, сохранив целостность главного окна приложения.
3. **Монопольное владение оборудованием:** На уровне GUI действует блокировка перехода между вкладками: пока активна сессия захвата в одном модуле, запуск другого видеомодуля заблокирован навигационными гардами.

### 2.2. Межпроцессный протокол обмена данными (IPC Packet Protocol)

Связь между дочерним процессом захвата и GUI-потоком реализована через однонаправленный канал `multiprocessing.Pipe(duplex=False)`. Дочерний процесс передает структурированные словари (пакеты), включающие:
- `preview_frame`: текущий кадр в формате RGB (хранится только последний поступивший кадр, что предотвращает утечки видеопамяти в кольцевой очереди);
- `samples`: буфер накопленных координатных измерений и физиологических отсчетов с монотонными таймстемпами;
- `record_bounds`: временные границы активного участка записи (`record_start`, `record_end`);
- `phase`: идентификатор фазы протокола (PREPARING, REST, SMILE, RECORDING и т.д.) и время входа в фазу `phase_start`;
- `status_text`: локализованная строка статуса для отображения врачу-исследователю;
- `done`: логический флаг успешного завершения сессии;
- `error`: текстовое описание исключения при сбое;
- `exit_reason`: кодовый идентификатор причины завершения (`completed`, `stopped`, `timeout`, `cancelled`).

Выемка пакетов из Pipe осуществляется неблокирующим образом по реактивному таймеру Qt (`QTimer(interval=33 ms)`), что обеспечивает частоту обновления видоискателя 30 FPS без задержек GUI.

### 2.3. Сторожевые таймеры (Watchdog Timers)

Супервизор сессии отслеживает дедлайны выполнения операций:
- `camera_startup_timeout` (10 с): таймаут ожидания поступления первого валидного видеокадра от камеры;
- `prepare_timeout` (15 с): максимальное время ожидания стабилизации пациента в начальной позе;
- `read_stall_timeout` (2 с): обнаружение зависания видеотракта (если между кадрами прошло более 2 секунд, сессия аварийно прерывается);
- `record_timeout`: жесткий предельный тайм-лимит на фазу записи;
- `voice_init_timeout` (120 с): расширенное время инициализации тяжелых аудиобиблиотек (JIT Numba в Librosa, Parselmouth).

При срабатывании таймера или нажатии кнопки «СБРОС» супервизор выставляет объект `multiprocessing.Event` (`stop_event`) для мягкого завершения, а при отсутствии отклика в течение 2 секунд вызывает `terminate()`.

## 4. Модуль 1: Анализ тремора верхних конечностей (`tremor_engine.py`, `capture_worker.py`)

### 4.1. Протокол видеозахвата и предварительная обработка

1. **Фаза подготовки (PREPARING, 2 секунды):** Пациент помещает кисть руки перед веб-камерой. Дочерний процесс `capture_worker.py` непрерывно отслеживает наличие стабильной детекции ключевых точек кисти через модель `HandLandmarker`. Если в течение 15 секунд рука не зафиксирована, генерируется таймаут.
2. **Фаза активной записи (RECORDING, 15 секунд):** После стабилизации фиксируются абсолютные физические временные метки кадров и двумерные пиксельные координаты дистальной фаланги указательного пальца (Landmark Index 8).
3. **Нормализация на масштаб кисти:** Для компенсации вариаций расстояния от руки до объектива камеры в каждом кадре рассчитывается длина анатомического базиса ладони — евклидово расстояние между запястьем (Landmark 0) и пястно-фаланговым суставом среднего пальца (Landmark 9):
   $$L_{palm} = \sqrt{(x_9 - x_0)^2 + (y_9 - y_0)^2}$$
   Координаты смещения нормализуются делением на среднее значение $L_{palm}$, что переводит измерения в безразмерные доли длины кисти.

### 4.2. Алгоритмы фильтрации и спектрального оценивания (`tremor_engine.py`)

1. **Критерии валидности сигнала (Quality Gates):**
   - Длительность полезного участка $\ge 10$ секунд;
   - Число отсчетов $\ge 200$;
   - Медианная частота дискретизации $F_s \ge 25$ Гц;
   - Доля пропущенных кадров не более 20% (покрытие $\ge 80\%$);
   - Максимальный непрерывный интервал выпадения кадров $< 0.2$ с;
   - Отсечение краевых переходных интервалов (первая и последняя 1.0 с исключаются из спектрального анализа).
2. **Интерполяция и удаление тренда:** Временной ряд координат $x(t)$ и $y(t)$ интерполируется на строгую равномерную временную сетку с шагом $\Delta t = 1 / F_s$, после чего выполняется раздельное удаление линейного тренда (detrending).
3. **Полосовая фильтрация Баттерворта:**
   - Порядок фильтра: 4-й (в форме каскада секций второго порядка, SOS);
   - Полоса пропускания: от 1,0 Гц до $F_{upper} = \min(12.0, 0.45 \cdot F_s)$ Гц;
   - Применяется нуль-фазовая прямая и обратная фильтрация (`scipy.signal.sosfiltfilt`), предотвращающая фазовые искажения биомеханических колебаний.
4. **Спектральная плотность мощности методом Велча (Welch PSD):**
   - Расчет PSD выполняется раздельно по осям X и Y: $P_{xx}(f)$ и $P_{yy}(f)$;
   - Результирующая мощность колебаний: $P_{total}(f) = P_{xx}(f) + P_{yy}(f)$;
   - Двумерное среднеквадратичное отклонение смещения (RMS):
     $$RMS = \sqrt{\frac{1}{N} \sum_{i=1}^N \left( x_{filt}[i]^2 + y_{filt}[i]^2 \right)}$$
5. **Спектральная концентрация и валидация доминирующего пика:**
   - Кандидат в доминирующую частоту $f_{peak}$ выбирается как глобальный максимум $P_{total}(f)$ в анализируемом диапазоне;
   - Спектральная концентрация $C_{peak}$ рассчитывается как доля мощности в окрестности $\pm 1.0$ Гц вокруг $f_{peak}$ относительно всей полосы;
   - Результат доминирующей частоты признается валидным только при выполнении жестких пороговых условий: отношение мощности пика к медианному шуму $\ge 4.0$, концентрация мощности $C_{peak} \ge 30\%$, значимая амплитуда RMS.

### 4.3. Клиническая дифференциация тремора

- **Диапазон 4,0–6,5 Гц (Паркинсонический паттерн):** Характерен для тремора покоя при болезни Паркинсона. В протоколе формируется индикация «ПАРКИНСОНИЧЕСКИЙ ДИАПАЗОН».
- **Диапазон 6,5–12,0 Гц (Постурально-кинетический паттерн):** Характерен для эссенциального или физиологического тремора.
- При отсутствии выраженного частотного пика (рассеянный спектр) результат классифицируется как отсутствие патологической ритмичности.

## 5. Модуль 2: Количественная оценка нейромимики и экспрессий (`facial_engine.py`, `face_capture.py`)

### 5.1. Трехэтапный протокол FAST-скрининга

Протокол направлен на объективизацию компонента **Face** шкалы FAST (Face-Arms-Speech-Time) для выявления лицевой асимметрии:
1. **Этап 1: Состояние покоя (REST, 3 секунды):** Пациент сохраняет нейтральное, расслабленное выражение лица.
2. **Этап 2: Проба улыбки (SMILE, 3 секунды):** Пациент максимально широко улыбается и удерживает мимику.
3. **Этап 3: Подъем бровей (BROWS, 3 секунды):** Пациент максимально высоко поднимает обе брови.

Входные ворота качества контролируют: присутствие строго одного лица в кадре, межосевое расстояние внешних уголков глаз $\ge 90$ пикселей, углы поворота головы ($|\text{Yaw}| \le 12^\circ$, $|\text{Pitch}| \le 12^\circ$, $|\text{Roll}| \le 25^\circ$), освещенность и отсутствие смаза (дисперсия лапласиана $\ge 12$).

### 5.2. Нормализация проекции и построение анатомической оси

MediaPipe FaceLandmarker генерирует 478 трехмерных ориентиров. В анализе геометрии лица используются первые 468 точек:
1. **Базисная трансформация по глазам:** Центр между внешними уголками глаз (точки 33 и 263) переносится в начало координат $(0, 0)$. Линия глаз поворачивается строго горизонтально (компенсация угла крена Roll). Все координаты масштабируются делением на ширину межглазного базиса $W_{eyes}$:
   $$W_{eyes} = \sqrt{(x_{263} - x_{33})^2 + (y_{263} - y_{33})^2}$$
2. **Робастная срединная ось лица:** По 4 срединным анатомическим точкам — глабелле (9), спинке носа (168), кончику носа (1) и подбородку (152) — методом МНК строится линия регрессии:
   $$x = \text{slope} \cdot y + \text{offset}$$
3. **Проекция билатеральных пар:** Для каждой анатомической пары ориентиров (правая точка $R$, левая точка $L$) вычисляются ортогональное расстояние до срединной оси $d_\perp$ и продольная координата вдоль оси $d_\parallel$. Погрешность билатеральной симметрии пары:
   $$\varepsilon_{pair} = 100 \times \frac{\sqrt{(|d_{\perp, R}| - |d_{\perp, L}|)^2 + (d_{\parallel, R} - d_{\parallel, L})^2}}{W_{eyes}}$$

### 5.3. Билатеральные метрики и индекс асимметрии лица (ASI)

- **Региональные погрешности:** Точки сгруппированы в 4 анатомические зоны (`PAIRS`): рот/носогубные складки, контуры глаз, линия бровей, щечные ориентиры. Для каждой зоны в каждом кадре берется медиана погрешностей пар.
- **Индекс асимметрии лица (ASI, Facial Asymmetry Index):** Рассчитывается как среднее арифметическое интегральных геометрических отклонений на всех трех этапах:
   $$ASI = \frac{Dev_{rest} + Dev_{smile} + Dev_{brows}}{3}$$
- **Дисбаланс подвижности (Excursion Imbalance):** Для улыбки и бровей рассчитывается процентное расхождение динамического смещения правой и левой стороны относительно покоя:
   $$Imbalance = 100 \times \frac{|\Delta_{right} - \Delta_{left}|}{\Delta_{right} + \Delta_{left}}$$

### 5.4. Дифференциация центрального vs периферического пареза

- **Центральный парез (поражение кортико-нуклеарного тракта / ОНМК):** Верхняя треть лица имеет двустороннюю корковую иннервацию, поэтому подвижность бровей сохранена, а асимметрия изолированно локализуется в нижнем сегменте (сглаженность носогубной складки, отставание угла рта при улыбке).
- **Периферический парез (нейропатия лицевого нерва / паралич Белла):** Поражение ядра или ствола VII черепного нерва приводит к тотальной гемиплегии мимических мышц на стороне поражения: одновременный выраженный дефицит улыбки и невозможность поднять бровь / закрыть глаз (лагофтальм).

## 6. Модуль 3: Бесконтактная фотоплетизмография / rPPG (`rppg_engine.py`, `rppg_capture.py`)

### 6.1. Локализация областей интереса (ROI) и экстракция сигнала

Бесконтактный мониторинг гемодинамики основан на регистрации микропульсаций поглощения света сосудистым руслом дермы лица:
1. **Анатомические полигоны:** На базе ориентиров Face Mesh формируются 3 выпуклые полигональные маски:
   - **Лоб (Forehead):** точки `(10, 109, 108, 151, 337, 338)`;
   - **Правая щека (Right Cheek):** точки `(50, 101, 205, 187)`;
   - **Левая щека (Left Cheek):** точки `(280, 330, 425, 411)`.
2. **Стягивание границ (Inset 75%):** Каждая область интереса пропорционально сжимается до 75% от исходного размера к своему геометрическому центру. Это исключает попадание краевых теней, волос, бровей и краев глазниц.
3. **Зеленый цветовой канал:** В каждом кадре для каждого ROI вычисляется пространственное среднее значение зеленого канала $G(t)$. Зеленый спектр (520–560 нм) совпадает с главным пиком поглощения оксигемоглобина, обеспечивая наивысшее отношение сигнал/шум.
4. **Фоновый референс:** Фоновый угол видеокадра вне зоны лица используется для непрерывного измерения внешних световых колебаний.

### 6.2. Цифровая фильтрация и спектральный расчет ЧСС

1. **Нормализация и детрендинг:** Сигнал $G(t)$ преобразуется в относительные процентные флуктуации вокруг локального среднего $\mu$:
   $$s(t) = \frac{G(t) - \mu}{\mu} \times 100\%$$
   Линейный тренд вычитается методом наименьших квадратов.
2. **Полосовой фильтр:** Полосовой фильтр Баттерворта 4-го порядка в полосе 0,75–3,0 Гц (соответствует физиологическому диапазону пульса 45–180 уд/мин). Нуль-фазовая фильтрация `sosfiltfilt` сохраняет форму волны.
3. **Быстрое преобразование Фурье (БПФ) с окном Ханна:** Вычисляется односторонний спектр мощности.
4. **Субдискретная параболическая интерполяция:** Для преодоления погрешности дискретизации частотной сетки координаты спектрального пика уточняются по формуле параболической аппроксимации трех точек логарифмического спектра вокруг бина максимума $k_{max}$:
   $$\delta = \frac{1}{2} \frac{\ln P[k_{max}-1] - \ln P[k_{max}+1]}{\ln P[k_{max}-1] - 2\ln P[k_{max}] + \ln P[k_{max}+1]}$$
   $$f_{interp} = (k_{max} + \delta) \cdot \Delta f, \quad BPM = f_{interp} \times 60$$

### 6.3. Многоуровневый контроль качества и защита от артефактов

- **Межзональная согласованность (Inter-ROI Agreement):** Минимум 2 из 3 областей интереса должны показать оценку ЧСС с расхождением не более 0,10 Гц (6 BPM).
- **Спектральная концентрация мощности:** Доля мощности в окрестности $\pm 0,15$ Гц вокруг пика должна составлять не менее 45% от общей внутриполосной мощности, а пик-к-медиане $\ge 8$.
- **Темпоральная стабильность:** Независимые оценки по первой и второй половине 30-секундной сессии должны сходиться с интегральной оценкой с точностью до 0,15 Гц (9 BPM).
- **Подавление помех движения и освещения:** Вычисляется взаимная корреляция между сигналом пульса и вектором смещения головы / колебаний фона. При коэффициенте корреляции $> 0.8$ измерение бракуется.

## 7. Модуль 4: Моторный таппинг-тест UPDRS 3.4 (`motor_engine.py`, `motor_capture.py`, `motor_protocol.py`)

### 7.1. Клинический протокол и кинематика смыкания пальцев

Модуль автоматизирует клинический тест постукивания пальцами (Finger Tapping, пункт 3.4 международной шкалы MDS-UPDRS), являющийся ключевым инструментом количественной оценки гипокинезии, брадикинезии и двигательной истощаемости:
1. **Протокол:** Пациент производит максимально быстрые и амплитудные ритмичные смыкания и размыкания большого и указательного пальцев в течение 10 секунд.
2. **Анатомические ориентиры:** Координаты кончика большого пальца (Landmark 4) и кончика указательного пальца (Landmark 8) отслеживаются с помощью `HandLandmarker`.
3. **Нормализованная апертура:** Евклидово расстояние между пальцами нормализуется на длину ладони (от запястья 0 до пястно-фалангового сустава 5):
   $$D(t) = \frac{\sqrt{(x_8(t) - x_4(t))^2 + (y_8(t) - y_4(t))^2}}{L_{palm}(t)}$$
   Нормализация обеспечивает полную независимость расчетов от перемещения руки ближе или дальше от объектива.

### 7.2. Цифровая фильтрация и локализация экстремумов

1. **Сглаживание полиномиальным фильтром Савицкого-Голея:** Сигнал расстояния $D(t)$ сглаживается с помощью `scipy.signal.savgol_filter(window_length=7, polyorder=2)`. Фильтр сохраняет форму, положение и крутизну кинематических пиков раскрытия и схлопывания, подавляя высокочастотный дрожащий шум трекинга.
2. **Детекция пиков и впадин (`find_peaks`):**
   - Локальные максимумы $A_{max}[k]$ соответствуют фазе максимального раскрытия пальцев;
   - Локальные минимумы $A_{min}[k]$ соответствуют моменту физического контакта пальцев;
   - Фильтрация по минимальной высоте и относительному расстоянию отсекает ложные микроколебания.

### 7.3. Количественные биомаркеры моторики

- **Частота / темп таппинга ($F_{tap}$, Гц):** Среднее количество завершенных циклов смыкания в секунду. Значение $< 2,5$ Гц свидетельствует о брадикинезии.
- **Межтаповые интервалы (ITI, Inter-Tap Intervals):** Временные промежутки $\Delta t_k = t_{peak}[k] - t_{peak}[k-1]$ между последовательными циклами.
- **Коэффициент вариации темпа ($CV_{tempo}$, %):** Показатель аритмичности и двигательной дисрегуляции:
   $$CV_{tempo} = \frac{\sigma_{ITI}}{\mu_{ITI}} \times 100\%$$
- **Декремент амплитуды (истощаемость движений):** Методом наименьших квадратов строится прямая регрессии по амплитудам пиков раскрытия:
   $$A_{max}[k] = S_{decay} \cdot k + A_0$$
   Отрицательный наклон регрессионной прямой ($S_{decay} < -0.015$) объективно фиксирует классический феномен истощения амплитуды (progressive decrement), патогномоничный для паркинсонизма.

## 8. Модуль 5: Айтрекинг и ассистивная клавиатура AAC (`gaze_engine.py`, `gaze_capture.py`, `aac_speech.py`, `phrase_graph.py`)

### 8.1. Трекинг радужки и инвариантность к наклону головы

Модуль предназначен для бесконтактной коммуникации пациентов с тяжелыми моторными дефицитами (боковой амиотрофический склероз / БАС, спинальная травма, синдром «запертого человека»):
1. **Анатомические точки радужки:** Модель `FaceLandmarker` с субмоделью Iris детектирует центры радужек (точки 468 для правого глаза и 473 для левого глаза) и контуры глазных щелей (точки 33, 133, 362, 263).
2. **Компенсация ориентации головы:** Относительное смещение радужки внутри глазной щели нормализуется с учетом углов тангажа (Pitch) и рыскания (Yaw), извлекаемых из матрицы трехмерной трансформации головы:
   $$\vec{G}_{norm} = \vec{G}_{raw} - \mathbf{M}_{head} \cdot \vec{K}_{corr}$$
3. **Фильтрация EMA и подавление микросаккад:** Позиция взора сглаживается экспоненциальным скользящим средним (EMA) с адаптивным коэффициентом сглаживания ($\alpha = 0.35$). Вводится пространственная зона нечувствительности (Deadzone 12 px), предотвращающая дрожание курсора при физиологических микросаккадах глаза. При моргании (падении вертикальной высоты глазной щели ниже порога) фильтр замораживает координаты.

### 8.2. Байесовская классификация и конечный автомат удержания (Dwell Engine)

1. **Гауссовский наивный байесовский классификатор:** Вероятность принадлежности текущей позиции взора $(x, y)$ к экранной карточке $C_i$ рассчитывается на основе двумерного нормального распределения:
   $$P(C_i \mid x, y) \propto P(C_i) \cdot \mathcal{N}\left(x; \mu_{x,i}, \sigma_{x,i}^2\right) \cdot \mathcal{N}\left(y; \mu_{y,i}, \sigma_{y,i}^2\right)$$
2. **Гистерезис переключения:** Переключение активного фокуса между соседними карточками происходит только тогда, когда апостериорная вероятность альтернативной карточки превосходит текущую на порог гистерезиса ($\Delta P > 0.20$), что исключает мерцание интерфейса на границах кнопок.
3. **Конечный автомат фиксации (Dwell Engine):**
   - **Фиксация (Dwell):** При непрерывном удержании взгляда на карточке в течение 900 мс запускается таймер выбора с отображением кругового прогресс-бара;
   - **Срабатывание (Trigger):** По истечении 900 мс карточка активируется, формируя речевое или логическое действие;
   - **Кулдаун (Cooldown):** Включается 500-миллисекундный период рефрактерности для предотвращения случайных повторных нажатий при переводе взгляда.

### 8.3. Речевой синтез и предиктивный марковский граф фраз

- **Локальный речевой синтез (pyttsx3):** Синтез русской речи осуществляется через нативный системный движок Microsoft SAPI5 в фоновом потоке без обращений к внешним сетевым API, обеспечивая 100% приватность и автономность в палатах интенсивной терапии.
- **Марковский граф подсказок (`PhraseGraph`):** Структура ориентированного взвешенного графа предсказывает вероятные последующие фразы на основе контекста предыдущего выбора:
   $$P(w_{t} \mid w_{t-1}) = \frac{Count(w_{t-1} \to w_t)}{\sum_k Count(w_{t-1} \to w_k)}$$
   Экран динамически подтягивает наиболее релевантные фразы-продолжения (например: «МНЕ БОЛЬНО» $\to$ «ГОЛОВА», «СПИНА», «НОГА»), сокращая время набора текста пациентом в 3–4 раза.

## 9. Модуль 6: Акустический анализ голоса (`voice_engine.py`, `voice_capture.py`, `voice_dependencies.py`)

### 9.1. Протокол аудиозахвата и автоматический триггер фонации

1. **Аппаратный ввод:** Захват одноканального аудиосигнала (моно, float32) с системной частотой дискретизации (16–96 кГц) через библиотеку `sounddevice` и PortAudio блоками по 1024 сэмпла.
2. **Пороговый запуск по энергии (RMS Onset Trigger):** Для исключения записи фоновой тишины запись 5-секундного измерительного буфера активируется только после превышения порога среднеквадратичной амплитуды $RMS \ge 0.005$ в течение не менее 80 мс подряд. Все предпусковые блоки отбрасываются.
3. **Контроль качества аудио:** Запись отбраковывается при клиппинге (доля сэмплов с амплитудой $\ge 0.99$ выше 0.1%), отношении сигнал/шум ниже 45 dBFS или доле невокализованных сегментов $> 15\%$.

### 9.2. Алгоритмы оценки основного тона (F0) и микродевиаций

Анализ устойчивой фонации гласного звука [а:] производится на основе стандарта MDVP (Multi-Dimensional Voice Program) и алгоритмов системы Praat:
1. **Частота основного тона (F0) по методу Бурсмы (Boersma Autocorrelation):**
   - Диапазон поиска: 75–500 Гц;
   - Временной шаг: 10 мс;
   - **Перекрестная верификация алгоритмом YIN:** В среде `librosa` независимо вычисляется траектория F0 по алгоритму YIN на копии сигнала, ресемплированной до 16 кГц. При расхождении медиан более 15% сессия бракуется для исключения октавных ошибок удвоения/деления тона.
2. **Импульсная синхронизация (Praat Periodic Pulses):** Точки голосовых циклов расставляются методом периодической кросс-корреляции с динамическим программированием.
3. **Метрики частотной нестабильности (Jitter):**
   - **Jitter (local):** Относительное среднее абсолютное отклонение между длительностями последовательных периодов $T_i$:
     $$\text{Jitter}_{local} = \frac{\frac{1}{N-1} \sum_{i=1}^{N-1} |T_i - T_{i+1}|}{\frac{1}{N} \sum_{i=1}^N T_i} \times 100\%$$
   - **Jitter (RAP, Relative Average Perturbation):** Трехпериодное сглаживание:
     $$\text{RAP} = \frac{\frac{1}{N-2} \sum_{i=2}^{N-1} \left| T_i - \frac{T_{i-1}+T_i+T_{i+1}}{3} \right|}{\frac{1}{N} \sum_{i=1}^N T_i} \times 100\%$$
4. **Метрики амплитудной нестабильности (Shimmer):**
   - **Shimmer (local):** Относительная вариация пиковых амплитуд $A_i$ смежных циклов:
     $$\text{Shimmer}_{local} = \frac{\frac{1}{N-1} \sum_{i=1}^{N-1} |A_i - A_{i+1}|}{\frac{1}{N} \sum_{i=1}^N A_i} \times 100\%$$
   - **Shimmer (APQ5):** Пятипериодная факторизация амплитудных возмущений.
5. **Гармоничность (HNR, Harmonics-to-Noise Ratio):** Отношение акустической энергии регулярных голосовых гармоник к диффузному турбулентному шуму в децибелах (дБ):
   $$HNR = 10 \cdot \log_{10} \frac{E_{harmonics}}{E_{noise}}$$
6. **Кепстральные коэффициенты (MFCC):** Извлечение первых 13 мел-кепстральных коэффициентов и построение нормализованной спектрограммы STFT (размер окна 1024, шаг 160) в динамическом диапазоне -80…0 дБ до 5 кГц.

### 9.3. Сравнение с клиническими нормативами MDVP

- **Jitter local $> 1,04\%$:** Признак нестабильности смыкания голосовых складок, характерный для ранней стадии дизартрии или гипофонии при паркинсонизме.
- **Shimmer local $> 3,81\%$:** Признак пареза голосовых складок или неполного смыкания голосовой щели при бульбарном/псевдобульбарном синдроме.
- **HNR $< 20$ дБ:** Свидетельствует о выраженной осиплости, дисфонии и примеси турбулентного воздушного шума.

## 10. Интеллектуальная система поддержки врачебных решений (CDSS) (`cdss_dashboard.py`, `session_diagnostics.py`)

### 10.1. Двудольная графовая онтология биомаркеров и синдромов

Интеграционным аналитическим ядром программного комплекса является подсистема поддержки принятия врачебных решений (Clinical Decision Support System, CDSS). В основе алгоритма лежит формализованный двудольный ориентированный граф онтологии клинических знаний $G = (V_B \cup V_S, E)$, реализованный с использованием библиотеки `networkx`:
- **Множество биомаркеров $V_B$ (9 вершин):**
  1. `TREMOR_PARKINSONIAN`: Спектральный пик тремора в полосе 4,0–6,5 Гц;
  2. `TREMOR_ESSENTIAL`: Спектральный пик тремора в полосе 6,5–12,0 Гц;
  3. `MOTOR_DECREMENT`: Выраженный декремент амплитуды пальцевого таппинга ($S_{decay} < -0.015$);
  4. `MOTOR_BRADYKINESIA`: Брадикинезия темпа таппинга ($F_{tap} < 2.5$ Гц);
  5. `FACIAL_LOWER_ASYMMETRY`: Изолированный дисбаланс нижней зоны лица (улыбка / носогубная складка);
  6. `FACIAL_COMBINED_ASYMMETRY`: Тотальный сочетанный дисбаланс улыбки и подвижности бровей;
  7. `VOICE_PERTURBATION`: Патологические пертурбации голоса (Jitter $> 1.04\%$, Shimmer $> 3.81\%$);
  8. `RPPG_TACHYCARDIA`: Синусовая тахикардия покоя (ЧСС $> 95$ BPM);
  9. `RPPG_BRADYCARDIA`: Синусовая брадикардия покоя (ЧСС $< 60$ BPM).
- **Множество синдромальных гипотез $V_S$ (6 вершин):**
  1. `PARKINSONISM`: Паркинсонический синдром;
  2. `ESSENTIAL_TREMOR`: Синдром эссенциального тремора;
  3. `CENTRAL_FACIAL_PARESIS`: Центральный парез мимической мускулатуры (подозрение на ОНМК / ТИА);
  4. `BELLS_PALSY`: Периферическая нейропатия лицевого нерва (паралич Белла);
  5. `BULBAR_SYNDROME`: Бульбарный / псевдобульбарный синдром;
  6. `AUTONOMIC_DYSFUNCTION`: Вегетативная кардиоваскулярная дисфункция.

### 10.2. Матрица весовых коэффициентов и семантика связей

Направленные ребра графа $e = (b \to s) \in E$ обладают знаковой доказательной силой:
- **`STRONGLY_SUGGESTS` (вес $+0.95$):** Высокоспецифичный патогномоничный биомаркер (например: `TREMOR_PARKINSONIAN` $\to$ `PARKINSONISM`, `FACIAL_LOWER_ASYMMETRY` $\to$ `CENTRAL_FACIAL_PARESIS`, `FACIAL_COMBINED_ASYMMETRY` $\to$ `BELLS_PALSY`);
- **`SUGGESTS` (вес $+0.60$):** Умеренная диагностическая связь (например: `MOTOR_DECREMENT` $\to$ `PARKINSONISM`, `VOICE_PERTURBATION` $\to$ `BULBAR_SYNDROME`);
- **`CORRELATES` (вес $+0.40$):** Неспецифическая коморбидная корреляция (например: `MOTOR_BRADYKINESIA` $\to$ `PARKINSONISM`, `RPPG_TACHYCARDIA` $\to$ `AUTONOMIC_DYSFUNCTION`);
- **`EXCLUDES` (вес $-0.75$):** Отрицательное дискриминирующее ребро (например: сохранность подвижности бровей или изолированная нижняя асимметрия резко снижает вероятность периферического паралича Белла в пользу центрального пареза).

### 10.3. Алгоритм вычисления индекса доказательной поддержки

Индекс синдромальной поддержки $I_S$ вычисляется путем нормирования взвешенной суммы активированных входящих ребер на максимально возможный теоретический положительный вес данного синдрома:
$$I_S = \max\left(0, \frac{\sum_{b \in B_{active}} w(b \to S)}{\sum_{b \in B, w(b \to S) > 0} w(b \to S)}\right) \times 100\%$$
Полученный процентный показатель градуируется по трем клиническим уровням:
- $0\% - 25\%$: Низкая вероятность гипотезы (зеленый индикатор);
- $26\% - 65\%$: Умеренная вероятность, требующая динамического наблюдения (желтый индикатор);
- $> 65\%$: Высокая вероятность синдрома, требующая срочной специализированной консультации невролога (красный индикатор).

Интерфейс `cdss_dashboard.py` интерактивно визуализирует топологию графа с помощью Matplotlib, подсвечивая активные ребра и узлы с цветовым кодированием силы связей.

## 11. Темпоральный граф пациентов и защита данных (`patient_graph.py`, `patient_cards_drawer.py`)

### 11.1. Архитектура темпорального графа `TemporalPatientGraph`

Для отслеживания динамики заболевания и эффективности проводимой терапии в комплексе реализована графовая темпоральная база данных на базе NetworkX, сериализуемая в локальный файл `patient_history_graph.json`:
- **Иерархия вершин:** `PATIENT -> SESSION -> (BIOMARKER, SYNDROME)`;
- **Узлы пациентов (Patient Nodes):** Содержат идентификатор пациента, метаданные и криптографический хеш пароля;
- **Узлы сессий (Session Nodes):** Хранят метку времени обследования, полные числовые значения биомаркеров и вычисленные индексы синдромов.

### 11.2. Темпоральные ребра `NEXT_SESSION` и классификация динамики

Между последовательными сессиями одного пациента формируется направленное хронологическое ребро `NEXT_SESSION`:
1. **Вектор приращений ($\Delta$-биомаркеры):** Для каждого количественного показателя рассчитывается дифференциальная разность:
   $$\Delta b_i = b_i(t_{current}) - b_i(t_{previous})$$
2. **Оценка клинического тренда:**
   - **«УЛУЧШЕНИЕ»:** Снижение амплитуды тремора, уменьшение асимметрии лица (ASI), рост темпа таппинга и снижение декремента истощаемости;
   - **«СТАБИЛЬНО»:** Колебания всех биомаркеров находятся в пределах доверительного интервала $\pm 5\%$;
   - **«УХУДШЕНИЕ»:** Рост асимметрии, нарастание тремора, падение регулярности моторики или углубление голосовых пертурбаций.

### 11.3. Поиск клинических прецедентов (Clinical Twins)

Алгоритм `find_clinical_twins` производит поиск наиболее схожих исторических сессий в базе данных для реализации метода прецедентного анализа (Case-Based Reasoning). Мера сходства рассчитывается как взвешенная сумма схожести профиля биомаркеров и синдромальных оценок:
$$Sim(S_1, S_2) = 0.4 \cdot Jaccard(B_1, B_2) + 0.6 \cdot \left(1 - \frac{\sum_{k} |Score_{1,k} - Score_{2,k}|}{\sum_k \max(Score_{1,k}, Score_{2,k})}\right)$$

### 11.4. Криптографическая защита персональных данных

Для обеспечения конфиденциальности медицинской тайны персональные карточки пациентов защищены:
- **Хеширование паролей по SHA-256:** Пароли пользователей и врачей обрабатываются криптографической функцией `hashlib.sha256()` с добавлением соли. В открытом виде пароли никогда не сохраняются на диске.
- **Изоляция картотеки (`patient_cards_drawer.py`):** Выдвижная панель картотеки блокирует отображение истории болезни, графа визитов и диагнозов до успешного ввода мастер-пароля.
- **Принцип минимизации данных:** Видеозаписи с веб-камеры и аудиозаписи с микрофона физически не сохраняются в файловую систему — сохраняются исключительно расчетные числовые биомаркеры и параметры графа.

## 13. Инструкция по сборке, запуску и верификации

### 13.1. Системные требования

- **Операционная система:** Windows 10 / Windows 11 (64-бит);
- **Интерпретатор Python:** Python 3.12 (поддерживается работа в виртуальном окружении `.venv`);
- **Оборудование:** Веб-камера с поддержкой разрешения от 640x480 @ 30 FPS, встроенный или внешний микрофон.

### 13.2. Развертывание окружения и установка зависимостей

В терминале PowerShell из корневой директории проекта:

```powershell
# Создание виртуального окружения
python -m venv .venv

# Активация виртуального окружения
.\.venv\Scripts\Activate.ps1

# Установка жестко зафиксированных версий библиотек
pip install -r requirements.txt
```

### 13.3. Запуск программного комплекса

```powershell
python app.py
```

При первом запуске модулей, использующих нейросетевые модели MediaPipe (`HandLandmarker`, `FaceLandmarker`), система автоматически скачает оптимизированные легковесные файлы весов `.task` в локальную поддиректорию `models/`. Все последующие запуски производятся полностью автономно без подключения к сети Интернет.

### 13.4. Автоматизированное тестирование и верификация

Комплекс оснащен всеобъемлющим набором регрессионных и модульных тестов, не требующих физического подключения веб-камеры или микрофона (аппаратные вызовы имитируются через синтетические сигналы и mock-объекты):

```powershell
# Запуск полного набора тестов в фоновом offscreen-режиме Qt
$env:QT_QPA_PLATFORM = "offscreen"
pytest tests -q
```

Ожидаемый результат прохождения тестов:
```text
330 passed, 78 subtests passed in ~90s
```
